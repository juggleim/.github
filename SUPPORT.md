# JuggleIM Support

Thank you for using JuggleIM. Choosing the right support channel helps maintainers respond efficiently and keeps public issue trackers actionable.

## Documentation

Start with these resources:

- [Product overview](https://www.juggle.im/docs/guide/intro/)
- [Quick deployment guide](https://www.juggle.im/docs/guide/deploy/quickdeploy/)
- [Client SDK documentation](https://www.juggle.im/docs/client/quickstart/android/)
- [Server API documentation](https://www.juggle.im/docs/server/api/)
- [JuggleIM website](https://www.juggle.im/)

## Integration and usage questions

Search the target repository's existing issues before opening a new question. When asking for help, identify the repository, version, platform, deployment mode, database, and what you have already tried.

The [Telegram Chinese community](https://t.me/juggleim_zh) is available for Chinese-language integration discussion.

## Bug reports

Use the bug report form in the affected repository when behavior appears incorrect and can be reproduced. Include minimal reproduction steps and sanitized diagnostic information.

Do not use a bug report for commercial inquiries, general architecture advice, or security vulnerabilities.

## Feature requests

Use the feature request form in the most relevant repository. Explain the user problem, affected scenarios and platforms, expected behavior, and alternatives you considered.

## Security vulnerabilities

Never disclose a vulnerability publicly. Follow the [Security Policy](./SECURITY.md) and use GitHub private vulnerability reporting in the affected repository.

## Commercial and deployment inquiries

For managed cloud, private deployment, licensing, or commercial support, use the contact channel on the [JuggleIM website](https://www.juggle.im/).
